# PHASE 2 — Database Schema & Data Retention Architecture
## ReplyGenie Chrome Extension

**Completed:** 2026-08-28  
**Tests:** 87 passed / 87 total (6 suites)  
**Syntax check:** All files pass `node --check`  
**Storage Engine:** IndexedDB (`ReplyGenieDB`, version 1) with reversible migrations + `chrome.storage` for profile settings

---

## Executive Summary

Prior to Phase 2, the audit (`docs/reports/PHASE_0_AUDIT.md`) established that ReplyGenie had **no structured database, no schema, and no entity tracking**. Features like reply engagement tracking, style signal evolution, pattern analytics, and prompt A/B testing were marked **NOT AVAILABLE**.

Phase 2 introduces a **high-performance, client-side relational/document IndexedDB storage engine** (`ReplyGenieDB`) running in the Manifest V3 service worker. It introduces four core object stores (`replies`, `voice_profiles`, `reply_patterns`, `generation_runs`), an execution audit log store (`retention_meta`), and an automated **Data Retention Engine** that enforces privacy-first TTLs without compromising AI learning loops.

All existing `chrome.storage.sync` profile keys and settings were **preserved without destruction or renaming**.

## 1. Storage Architecture & Reversible Migrations

### Technology Choice: Client-Side IndexedDB
- **Location:** Runs natively inside Chrome Extension Manifest V3 Service Worker (`src/background/db/`).
- **Zero Third-Party Database Infrastructure:** Fits the bring-your-own-API-key, zero-backend model.
- **Database Name:** `ReplyGenieDB`
- **Current Version:** `1`

### Reversible Migration Engine (`src/background/db/migrations.js`)
Migrations define both forward (`up`) and backward (`down`) operations to guarantee zero data loss and clean rollback capability:


## 3. Data Retention Policy & Automated Cleanup

### Retention Policy Rules

1. **Raw Untrusted Source Tweet Text (`source_tweet_text`) — 90-Day TTL:**
   - **Policy:** Raw third-party tweet text from X is retained for **90 days maximum**.
   - **Action:** At 90 days, `runDataRetentionJob()` redacts `source_tweet_text` to `"[PURGED_RETENTION_TTL]"` and sets `raw_text_purged = 1`.
   - **Privacy & AI Trade-off:** Preserves the user's generated reply text, aggregated performance metrics, strategy labels, quality scores, and vector embeddings indefinitely so learning is never lost, while ensuring third-party text is purged in accordance with privacy best practices.

2. **Transient Generation Runs — 30-Day TTL:**
   - **Policy:** Generation runs with status `"rejected"`, `"error"`, or `"rate_limited"` (not linked to an accepted reply) are purged after **30 days**.
   - **Action:** Permanently deleted from `generation_runs` store to conserve local storage space.

3. **Decision Trace Logs — 14-Day TTL:**
   - **Policy:** Transient trace logs in `chrome.storage.local` are pruned to entries within the last 14 days.

4. **GDPR Right to be Forgotten / Total Reset:**
   - **API:** `purgeAllUserData()` completely erases all IndexedDB stores (`ReplyGenieDB`) and resets local storage profiles.

### Automated Scheduler (`src/background/db/retention.js`)
Uses `chrome.alarms` with `periodInMinutes: 1440` (once every 24 hours) under alarm name `replygenie_retention_cleanup`. Triggered safely in the background service worker lifecycle.
